### 今日目标
理解什么是异常；掌握 try-except-else-finally 完整结构；学会捕获指定异常、拿到错误信息；给脚本加上容错，出错不崩溃。

### 结构速查
```python
while True:
    try:
        # 可能出错的代码（输入、类型转换、运算）
    except 异常类型 as e:
        # 命中对应异常时处理，e 是错误信息
    else:
        # try 里没出错才执行
    finally:
        # 无论出不出错都执行（收尾/清理）
```

### 常用内置异常
| 异常 | 触发场景 |
|---|---|
| `ZeroDivisionError` | 除数为 0 |
| `TypeError` | 类型不对（字符串和数字相加） |
| `IndexError` | 列表下标越界 |
| `KeyError` | 字典取不存在的键 |
| `ValueError` | 值不合法（int("abc")） |

### 三条规矩
1. 优先抓具体异常，不写裸 `except:`，避免把真正的 bug 一起吞掉。
2. `else` 放「依赖 try 成功才能跑」的代码，不要全塞进 try。
3. `finally` 只做收尾清理（关文件、断连接、结束提示），禁止放 `break` / `return` / `continue`。

### 口述自测（答案）
1. **try-except 解决什么问题？不捕获会怎样？**
   try-except 用来捕获并处理运行时抛出的异常（除零、类型不对、越界等）：把可能出错的代码放 try 里，出错时跳进对应 except 分支容错，避免程序中断。如果不捕获，异常会抛到最外层，打印一长串 traceback，然后程序终止退出，后面的代码不再执行。

2. **else 和 finally 各自什么时候执行？**
   - else：try 里没有抛出任何异常（成功跑完）时才执行，放成功后的后续逻辑。
   - finally：无论 try 成功还是被 except 接住，都一定会执行，放收尾清理动作。

3. **为什么不建议写裸 `except:`？**
   裸 except 不区分错误类型，会把所有异常一网打尽，包括本来想暴露、想早点发现的 bug（变量名写错、逻辑错误等），全被静默吞掉，表面没报错、实际问题被掩盖，后面更难定位。应优先抓具体异常，让预料之外的错误照常暴露。

4. **`except 异常类型 as e` 里的 `e` 是什么？**
   e 是被捕获到的异常对象，相当于系统递来的错误报告单，里面存着错误类型和错误描述文字；print(e) 可输出系统报错原话。e 只是变量名，写成 as err 也可以。

5. **finally 里适合放什么代码？有什么坑？**
   适合放收尾、清理类代码：结束提示、关闭文件、断开连接、释放资源——这些动作无论成功失败都必须做。坑：finally 里禁止放 break / return / continue 这类改变流程的语句；因为 finally 必执行，break 会强行跳出循环，return 会覆盖前面的返回值。今天踩的坑就是 finally 里写 break，导致一轮结束就退出循环。

### 踩坑记录
- 路径与运行命令不一致 → `[Errno 2] No such file or directory`：先确认文件实际位置，命令路径与之对应。
- ValueError 写在函数外面：except 只能抓 try 内部抛出的异常，输入和类型转换要一起放进 try。
- finally 里写 `break`：finally 每轮必执行，会强行跳出循环，导致一轮就退出；finally 只做收尾打印。
